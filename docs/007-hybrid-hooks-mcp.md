# 007 -- Hybrid Hooks + MCP Optimization

## Overview

Future optimization on top of pure MCP (Phase 2). Replace 3 of 5 MCP tools with Claude Code hooks. Hooks handle predictable session-lifecycle ops (context injection, activity reporting) at zero tool-call token cost. 2 interactive MCP tools remain. Includes A/B comparison to validate savings with real data.

## Context

Current plan: 5 MCP tools via SSE transport. Every session, agent calls `get_organization_context` + `get_shared_memory` at start, `report_activity` at end. These 3 are lifecycle-predictable -- same call every time, no user input needed. Each tool registration adds ~200-400 tokens of schema to context window. Each call adds ~50-100 tokens of JSON-RPC overhead.

Claude Code hooks (`.claude/hooks/`) run shell commands at lifecycle points. Output injected into conversation via stdout. No tool schema, no JSON-RPC, no round-trip overhead.

## Goals

- Cut per-session token overhead by eliminating 3 predictable tool calls
- Maintain full functionality -- hooks deliver same data
- Keep interactive tools (`search_decisions`, `get_recent_activities`) as MCP
- Measure actual savings via A/B comparison before committing
- Zero breaking changes for existing pure-MCP users

## Non-Goals

- Replacing MCP server entirely
- Custom Claude Code extensions/plugins
- Client-side caching
- Changing data model or API shape

## Hybrid Architecture

### Tool Distribution

| Tool | Pure MCP | Hybrid | Why |
|------|----------|--------|-----|
| `get_organization_context` | MCP tool | `UserPromptSubmit` hook | predictable, every session, no input |
| `get_shared_memory` | MCP tool | `UserPromptSubmit` hook | predictable, every session, default params |
| `report_activity` | MCP tool | `Stop` hook | predictable, every task end |
| `search_decisions` | MCP tool | MCP tool | interactive, needs query input |
| `get_recent_activities` | MCP tool | MCP tool | interactive, optional, parameterized |

### Flow Comparison

**Pure MCP (current):**
```
Session start
  -> Claude discovers 5 tools (~1000-2000 tokens of schemas in context)
  -> Agent calls get_organization_context (tool call overhead)
  -> Agent calls get_shared_memory (tool call overhead)
  -> Agent works, may call search_decisions / get_recent_activities
  -> Agent calls report_activity (tool call overhead)
```

**Hybrid:**
```
Session start
  UserPromptSubmit hook fires
    -> curl /api/orgs/:slug/context-bundle (REST, not MCP)
    -> stdout: org vision + shared memory as markdown
    -> injected into conversation (zero tool tokens)
  -> Claude discovers 2 tools (~400-800 tokens of schemas)
  -> Agent works, may call search_decisions / get_recent_activities
  Stop hook fires
    -> extracts summary from conversation
    -> curl POST /api/orgs/:slug/activities (REST)
    -> fire-and-forget
```

### Token Savings Estimate

| Component | Pure MCP | Hybrid | Delta |
|-----------|----------|--------|-------|
| Tool schemas in context | ~1000-2000 | ~400-800 | -600 to -1200 |
| get_organization_context call | ~150 | 0 | -150 |
| get_shared_memory call | ~100 | 0 | -100 |
| report_activity call | ~150 | 0 | -150 |
| **Total overhead/session** | **~1400-2400** | **~400-800** | **~-1000 to -1600** |

Content tokens (actual vision docs, memories, activity summaries) identical in both modes.

### UserPromptSubmit -- Context Injection

Fires before every user prompt processed. Guard ensures single injection per session.

```bash
#!/bin/bash
# .claude/hooks/UserPromptSubmit/aigent-context.sh

AIGENT_API="${AIGENT_API_URL:-https://api.aigent.community}"
AIGENT_TOKEN="${AIGENT_TOKEN}"
AIGENT_ORG="${AIGENT_ORG}"

# inject once per session (PID-based guard)
GUARD="/tmp/aigent-ctx-${AIGENT_ORG}-$$"
[ -f "$GUARD" ] && exit 0
touch "$GUARD"

RESPONSE=$(curl -sf \
  -H "Authorization: Bearer ${AIGENT_TOKEN}" \
  "${AIGENT_API}/api/orgs/${AIGENT_ORG}/context-bundle")

[ $? -ne 0 ] && exit 0  # non-fatal

echo "--- ORGANIZATION CONTEXT (aigent) ---"
echo "$RESPONSE" | jq -r '.vision[] | "## [\(.category)] \(.title)\n\(.content)\n"'
echo "--- SHARED MEMORY ---"
echo "$RESPONSE" | jq -r '.memories[] | "- [\(.category)] \(.content)"'
echo "--- END ---"
```

### Stop -- Activity Reporting

Fires when agent finishes response. Reports activity automatically.

```bash
#!/bin/bash
# .claude/hooks/Stop/aigent-report.sh

AIGENT_API="${AIGENT_API_URL:-https://api.aigent.community}"
AIGENT_TOKEN="${AIGENT_TOKEN}"
AIGENT_ORG="${AIGENT_ORG}"

INPUT=$(cat)

# only report on end_turn, not mid-conversation tool calls
STOP_REASON=$(echo "$INPUT" | jq -r '.stop_reason // "end_turn"')
[ "$STOP_REASON" = "tool_use" ] && exit 0

SUMMARY=$(echo "$INPUT" | jq -r '.last_assistant_message // empty' | head -c 2000)
[ -z "$SUMMARY" ] && exit 0

FILES_CHANGED=$(git diff --name-only HEAD 2>/dev/null | jq -R -s 'split("\n") | map(select(length > 0))')

curl -sf -X POST \
  -H "Authorization: Bearer ${AIGENT_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "$(jq -n \
    --arg summary "$SUMMARY" \
    --argjson files "${FILES_CHANGED:-[]}" \
    '{summary: $summary, filesChanged: $files}')" \
  "${AIGENT_API}/api/orgs/${AIGENT_ORG}/activities" > /dev/null &
```

## A/B Comparison Mechanism

### Metrics

| Metric | Source | Unit |
|--------|--------|------|
| tool_call_count | MCP server logs | count/session |
| tool_schemas_token_estimate | static measurement per mode | tokens |
| tool_call_latency | MCP server per-call timing | ms |
| hook_execution_time | hook self-reporting | ms |
| hook_failure_rate | hook self-reporting | % |
| context_bundle_latency | REST endpoint timing | ms |
| activity_report_completeness | field comparison | score 0-1 |
| session_count | MCP server | count |

**Token estimation**: can't get exact counts externally. Measure byte size of injected content, apply ~4 chars/token heuristic. Relative comparison still valid even if absolute numbers off.

### Instrumentation -- MCP Server

Telemetry middleware wraps every tool call and REST endpoint:

```ts
// apps/data-service/src/telemetry/metrics.ts

interface ToolCallEvent {
  toolName: string
  orgId: string
  userId: string
  mode: 'pure_mcp' | 'hybrid'
  latencyMs: number
  responseBytes: number
  timestamp: string
}

interface HookEvent {
  hookName: string
  orgId: string
  latencyMs: number
  success: boolean
  timestamp: string
}
```

### Instrumentation -- Hook Scripts

Hooks self-report execution metrics (fire-and-forget, non-blocking):

```bash
START_TIME=$SECONDS
# ... hook logic ...
ELAPSED=$(( SECONDS - START_TIME ))

curl -sf -X POST \
  -H "Authorization: Bearer ${AIGENT_TOKEN}" \
  "${AIGENT_API}/api/telemetry/hook" \
  -d "{\"hook\":\"UserPromptSubmit\",\"latencyMs\":$((ELAPSED*1000)),\"success\":true}" &
```

### Storage

New `telemetry_event` table:

```sql
CREATE TABLE telemetry_event (
  id TEXT PRIMARY KEY,
  org_id TEXT NOT NULL,
  user_id TEXT,
  event_type TEXT NOT NULL,        -- 'tool_call' | 'hook_execution' | 'session'
  mode TEXT NOT NULL,               -- 'pure_mcp' | 'hybrid'
  payload JSONB NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_telemetry_mode_date ON telemetry_event(mode, created_at);
CREATE INDEX idx_telemetry_org ON telemetry_event(org_id, created_at);
```

### Feature Flag -- Per Org

```sql
ALTER TABLE organization ADD COLUMN delivery_mode TEXT DEFAULT 'pure_mcp';
```

```ts
type DeliveryMode = 'pure_mcp' | 'hybrid'
```

MCP setup page shows different instructions based on org's `delivery_mode`. MCP server checks `mode` query param to decide tool registration.

### Test Cohorts

| Week | Action |
|------|--------|
| 1-2 | all orgs `pure_mcp`, collect baseline |
| 3-4 | 50% of **new** orgs assigned `hybrid` (deterministic hash on orgId). existing orgs unchanged |
| 5-6 | analyze results, decide |
| 7+ | default all new orgs to winner. offer opt-in toggle for existing orgs. sunset loser after grace period |

Assignment:

```ts
function assignDeliveryMode(orgId: string): DeliveryMode {
  const hash = simpleHash(orgId)
  return hash % 2 === 0 ? 'hybrid' : 'pure_mcp'
}
```

## Migration Path

### Phase A -- Prepare (no user impact)

1. Add `delivery_mode` column to `organization` (default `pure_mcp`)
2. Add `telemetry_event` table
3. Create `/api/orgs/:slug/context-bundle` REST endpoint
4. Create `/api/telemetry/hook` endpoint
5. Instrument existing MCP tools with telemetry
6. Collect baseline 2 weeks

### Phase B -- Build Hook Infrastructure

1. Create hook script templates (bash)
2. Update MCP setup page: detect `delivery_mode`, show hook setup for hybrid orgs
3. "Download hooks" button generates zip with pre-filled env vars:
   ```
   .claude/hooks/UserPromptSubmit/aigent-context.sh
   .claude/hooks/Stop/aigent-report.sh
   .claude/hooks.json
   .claude/mcp.json
   ```
4. Add `mode` query param support to MCP SSE endpoint

### Phase C -- A/B Test

1. Assign 50% new orgs to hybrid
2. Collect 2-4 weeks
3. Admin reviews comparison dashboard

### Phase D -- Converge

- Hybrid wins: default new orgs, offer migration toggle for existing
- Pure MCP wins: keep as-is, hooks as optional power-user feature
- Sunset loser after grace period

### Backward Compatibility

- Pure MCP always available (all 5 tools)
- Hybrid orgs can fall back -- if hooks fail, agent still works (just no auto-context)
- MCP server supports both modes simultaneously
- Same DB schema, same `activity_log` format, no data migration

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Hook API unstable (Claude Code hooks are new) | high | fallback to pure MCP, hooks additive |
| Windows shell incompatibility | medium | PowerShell equivalent or WSL recommendation |
| `jq` not installed | medium | setup script checks deps |
| Stop hook misses session end (crash/kill) | medium | gaps acceptable, visible in dashboard |
| Token estimation inaccuracy | low | relative comparison valid |
| Guard file stale on crash | low | `/tmp` auto-clears |

- `UserPromptSubmit` stdout -- becomes system context or user message? affects agent interpretation
- Guard file vs Claude Code session state API? hooks may get session-level state in future
- Windows priority? if mostly mac/linux users, defer PowerShell
- 4 chars/token heuristic accurate enough? or need tiktoken for comparison
- `context-bundle` KV caching? vision docs rarely change, short TTL would help
- Hook timeout defaults in Claude Code? if <5s hard limit, slow connections fail
- Should Stop hook extract `decisionsMade`? or keep server-side only (Phase 4)
- 2 weeks baseline + 2-4 weeks test -- enough for statistical significance at expected volume?
